2. The pi-gen OS Build Commands (WSL)
Building an entire operating system locally can wreck your host environment if you install all the raw dependencies directly into WSL. The industry standard is to use pi-gen's built-in Docker wrapper so the OS compiles inside a clean, isolated container.
Here is the exact sequence of terminal commands to bake your setup-portal and your dual-screen labwc Wayland scripts into a custom .img file.
Step A: Compile the Setup Portal First, ensure your captive portal is built as a static HTML export.
cd ~/code/sous.tools
pnpm --filter setup-portal build
Step B: Clone & Configure pi-gen We will clone the official Raspberry Pi image builder and create a custom config file.
cd ~
git clone https://github.com/RPi-Distro/pi-gen.git
cd pi-gen

# Create the OS build configuration
cat <<EOF > config
IMG_NAME="sous-os-latest"
TARGET_HOSTNAME="soustools-node"
ENABLE_SSH=1
STAGE_LIST="stage0 stage1 stage2 stage3 stage4"
EOF
(Note: stage4 is the standard stage that includes the minimal desktop/Wayland environment).
Step C: Inject the "Chef-Proof" Scripts We are going to create a custom injection folder inside stage4 so pi-gen bakes your code directly into the root filesystem (ROOTFS_DIR) of the image.
# Create the custom injection directory
mkdir -p stage4/00-soustools/files

# Copy the exported Next.js captive portal
mkdir -p stage4/00-soustools/files
cp -r ~/code/sous.tools/apps/setup-portal/out stage4/00-soustools/files/setup-portal

# Copy your Wayland/Kiosk dual-screen scripts
cp ~/code/sous.tools/deploy/ansible/roles/config/files/kiosk.sh stage4/00-soustools/files/
cp ~/code/sous.tools/deploy/ansible/roles/config/files/labwc-rc.xml stage4/00-soustools/files/
Step D: The Build Instructions Script We need to tell pi-gen exactly where to put these files inside the Raspberry Pi when it builds the image.
cat << 'EOF' > stage4/00-soustools/00-run.sh
#!/bin/bash -e

# Move the captive portal to a dedicated opt/ directory
mkdir -p "${ROOTFS_DIR}/opt/sous-tools/portal"
cp -r files/setup-portal/* "${ROOTFS_DIR}/opt/sous-tools/portal/"

# Install the dual-screen Chromium launch script
install -m 755 files/kiosk.sh "${ROOTFS_DIR}/usr/local/bin/kiosk.sh"

# Install the Wayland window rules mapping SignageOne to TV1 and SignageTwo to TV2
mkdir -p "${ROOTFS_DIR}/etc/labwc"
install -m 644 files/labwc-rc.xml "${ROOTFS_DIR}/etc/labwc/rc.xml"
EOF

# Make the script executable
chmod +x stage4/00-soustools/00-run.sh
Step E: Bake the Image Trigger the Docker build. This will take anywhere from 30 minutes to an hour depending on your machine, as it is literally compiling Debian packages and assembling a full operating system.
# Run the Dockerized build process
./build-docker.sh
The Result
When the script finishes, look inside the pi-gen/deploy/ directory. You will find your raw sous-os-latest.img file.
Flash that .img to your SD card using Raspberry Pi Imager or BalenaEtcher. When you plug it into your dev Raspberry Pi and boot it up, it will inherently possess your Wayland window rules and the entire static captive portal app sitting right there in /opt/sous-tools/portal/!
